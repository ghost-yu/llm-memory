## 2. 问题和贡献：选择记什么，也决定怎样改

聊天历史直接进入上下文时，成本随历史增长；普通 RAG 保存文本块，可能把大量无关内容一起召回，也不会自然消除旧事实。“我住北京”与“我搬到杭州了”如果都作为普通相似文本存在，回答器必须自行判断时间及冲突。Mem0 把这种决策放到写入阶段：先抽取持久事实，再比较已有记忆，选择新增、补充/更新、删除或不操作。读阶段只取相关记忆交给回答模型。

【必须会】区分原始消息、候选事实、已保存记忆、检索给回答器的上下文。候选并不自动进入数据库。相似度不是冲突检测器；“喜欢北京”和“住北京”很相似，却可以同时成立。实际动作依赖 LLM 对语义的判断。

同前几篇的联系：Titans/MIRAS 在模型计算里写神经记忆；Nested Learning 讨论更新频率与优化层级；MemGPT 管理有限主上下文和外部工具调用；Mem0 更专注外部持久事实的抽取与归并。数据库持久化不会改变底层 LLM 参数。记住一个事实、检索到该事实、正确用它回答，是三件不同的事。

## 3. 基础 Mem0：一个完整样本穿过图2

图2的左侧输入新消息对；紫色抽取区接收历史摘要、近期消息和新交互；底部输出候选记忆。绿色更新区先取相似旧记忆，随后 LLM 选择操作；右侧把结果写回数据库。顶部 Summary Generator 是独立异步组件，为后续抽取提供概要，不应理解成“每次 add 都同步总结全部历史”。图中的箭头表示数据与调用关系，并不表示反向传播。

样本：旧事实“用户住北京”，新交互“我上周搬到杭州了”。摘要帮助确定用户，近期消息帮助解析“上周”，候选可能为“用户从上周起住杭州”。检索返回与居住地相关旧事实；更新模块决定覆盖当前居住地或处理冲突。若需要过去住址，必须明确设计历史记录/时间字段，不能只靠当前事实快照回答所有过去时问题。

### 3.1 抽取与数据类型

论文 §2.1 使用未编号记号：

$$P=(S,\{m_{t-m},\ldots,m_{t-2}\},m_{t-1},m_t),\qquad\Omega=\phi(P)=\{\omega_1,\ldots,\omega_n\}.$$

S 是整个历史的摘要字符串；m_t 为当前消息，m_(t-1) 为前一条；m 控制近期窗口，论文设置 m=10；P 是构建的提示文本；φ 是 LLM 抽取函数；Ω 是 n 个候选记忆字符串。论文列出的近期索引从 t-m 到 t-2，按闭区间计数为 m-1，不应一边照抄索引一边声称精确有 m 条；工程实现必须单独定义切片约定。新消息对和旧窗口也应避免重复。

这些符号不是训练张量。字符串经过 tokenizer 后才变成整型 token 序列 [L]，批处理可为 [B,L]；候选是 list[str]，n 随输入变化。论文没有公开固定候选数或在此公式定义损失。示例：S=“Alice 是用户”，新消息=“我住杭州，喜欢骑行”，理想 Ω 含居住地和爱好两项；抽取错误时，后续检索和数据库都可能忠实保存错误。

### 3.2 检索与四种动作

每个 $\omega_i$ 嵌入为 $e_i\in\mathbb R^d$，数据库中的旧记忆可写成 $E\in\mathbb R^{N\times d}$。d 是 embedding 后端决定的维数，不是论文固定的新网络宽度。以下是帮助理解相似检索的公式，不是论文编号方程：

$$\operatorname{sim}(e_i,e_j)=\frac{e_i^\top e_j}{\|e_i\|_2\|e_j\|_2}.$$

步骤是编码、归一化或后端等价距离计算、按身份筛选、排序、取 top-s。两个二维向量 (1,0) 与 (0.8,0.6) 均为单位向量，余弦为 0.8；(0,1) 得 0。高分只表示嵌入接近，不能推导事实成立或矛盾。论文 s=10；锁定代码写死 limit=5。demo 使用 64 维词哈希计数和单位化向量，Python list[float]，不冒充语义嵌入。

| 动作 | 用途 | 教学例子 | 对当前存储的影响 |
|---|---|---|---|
| ADD | 新信息无合适已有项 | 新增爱好 cycling | 新 UUID、新记录 |
| UPDATE | 已有信息需补充/改写 | Beijing → Hangzhou | 同 UUID 改文本，记旧/新历史 |
| DELETE | 移除不再成立的项 | 删除原爱好 | 移出活动向量集合，留下历史 |
| NOOP | 无变化 | 重复 Hangzhou | 不写入 |

论文强调 UPDATE 为补充、DELETE 为矛盾信息移除；真实动作也受提示词的例子与任务定义影响。“搬家”可以采用 UPDATE，不能认为论文强制所有矛盾一律覆盖。锁定项目使用字符串 NONE 对应 NOOP。不能向这份代码发送 NOOP 并假定得到 NONE 的行为。

【必须会】取 top-s 的目的是缩小比较范围；数据库没有全局一致性证明。相关旧项若没进 top-s，LLM 可能误判 ADD。多个相关事实在一次调用中归并，也可能产生部分成功，必须查看结果和实际存储。


### 3.3 把符号与实际“形状”接起来【必须会】

抽取式中t是消息时间索引，m是窗口参数，n是抽出的事实数量；下标i=1…n枚举候选，不是batch维。P在论文中用元组表示提示内容的来源，实际送给模型时要序列化成消息列表/文本；S与每条m均为字符串，Ω为变长list[str]。φ是固定底层模型的推理调用，本流水线没有对φ的新训练loss。真实LLM分词得到int序列[L]，但本地Provider直接匹配字符串，没有实测任何token Tensor。

检索式中e_i/e_j各是[d]浮点向量，点积与两个范数都是标量；在N旧项上计算会得到[N]分数，再筛身份/选top-s。需要非零向量才能直接用这个数学式。demo Embedder只保留正则[a-z]+的英文词，将SHA-256前缀取模64后累计，再除L2范数；哈希冲突不等于语义相近。新实测'中文123'没有英文词，得到64个0；本地Vectors仍返回Alice的score=0记忆，因为没有最低分数阈值。因此“返回一项”不能当作“语义命中一项”。这个边界只属于替代后端，不归因于真实embedding模型。

图2从Messages→紫色Extraction→候选→绿色Update→新记忆→数据库，再从数据库向下返回旧记忆/历史摘要。抽取/更新/摘要LLM与embedding模型有预训练参数，当前操作是模型调用，不在图中训练它们；相似搜索、临时ID映射、SQLite操作本身无可训练权重。图中Tool Call是论文设计，本commit的向量路径用JSON动作数组，箭头不会自动变成5个工具函数或backprop。选s=10与代码limit=5不同必须标出；m窗口也不能从本地parse_messages自行推断已实现。

以city=Beijing→city=Hangzhou串一次实际路线：messages从str变单条user dict列表；parse得到str；提取返回JSON str→facts list[str]；每条编码list[float]长64；旧项list[object(id,payload,score)]→去重后list[dict(id,text)]→id映射数字str；更新响应JSON str→动作list[dict]；原UPDATE用映射回UUID→payload/向量写入→历史库追加→search返回Pydantic组织的dict。数据库节点数N变化，不固定为网络序列长L。

## 4. 原代码核心路径和 Python 语义

### 4.1 add：封装身份与并行后端

[Memory.add](代码/mem0-historical/mem0/memory/main.py) 从第107行开始。owner 为 Memory；输入 messages 为字符串或消息字典列表，user_id/agent_id/run_id 默认 None，infer 默认 True。它把身份同时放入 filters 和 metadata，至少要求一种身份；字符串转成 role=user 的单项列表；随后用 ThreadPoolExecutor 调用向量和图分支。v1.1 返回 dict，基础版本形如 {results: [...]}；启用图时还包含 relations。函数改变数据库与历史，不训练 LLM。

原代码关键摘录：

~~~python
if user_id:
    filters['user_id'] = metadata['user_id'] = user_id
future1 = executor.submit(self._add_to_vector_store, messages, metadata, filters, infer)
future2 = executor.submit(self._add_to_graph, messages, filters)
vector_store_result = future1.result()
~~~

连等赋值给两个字典保存同一身份字符串；self 是所属对象，点号访问其配置/后端；submit 返回 Future，result 等待并取结果，也会传播线程中的未捕获异常。并行两分支不等于两数据库原子事务；若图失败而向量已成功，不能仅看顶层抛异常就认为没有写入。demo 关闭图，保留原线程调用。

变量表：messages 是 list[dict]，filters/metadata 是 dict，future1/2 是 Future，vector_store_result 是 list[dict]。这是一条 Python 数据对象流，不存在 attention heads 或 hidden-state shape。图分支关闭时原 _add_to_graph 返回空列表。

### 4.2 _add_to_vector_store：候选不是最终事实

从第203行开始。infer=False 分支逐条存非 system 消息，跳过抽取与归并；它不是“同样算法但更快的推理”。infer=True 先 parse_messages，再生成事实提示，LLM 返回 JSON 的 facts 字段。随后每个候选嵌入、查询 top5、合并重复旧项，并把 UUID 临时映射为数字字符串。

~~~python
existing_memories = self.vector_store.search(
    query=new_mem, vectors=messages_embeddings, limit=5, filters=filters)
for idx, item in enumerate(retrieved_old_memory):
    temp_uuid_mapping[str(idx)] = item['id']
    retrieved_old_memory[idx]['id'] = str(idx)
~~~

这样 LLM 可以引用“0”而不必正确复制长 UUID。enumerate 给出索引与元素；str(idx) 与 JSON ID 一致。temp_uuid_mapping 是 dict[str,str]；retrieved_old_memory 是 list[{id:str,text:str}]；new_message_embeddings 是 dict[str,list[float]]。old items 去重后，更新提示实际上可合并多个候选共同决策，不完全等于论文逐候选的伪代码顺序。

第二次 LLM 调用返回 memory 动作数组。ADD 调用 _create_memory；UPDATE/DELETE 把临时编号翻译回 UUID；NONE 只记录日志。结果列表包含已执行动作，不包含 NONE，因此空 results 可能是无变化，也可能是解析错误或动作失败，不能直接当“成功且已去重”。该函数捕获多处异常并继续。本实验特意给出 BAD_JSON，记录日志错误同时检查存储未变。

【必须会】同论文图2的三个差异：这里传入的 messages 被直接拼接，没有在 add 路径实现论文完整的历史摘要+最近窗口后台流水线；比较数量为5而非10；所读基础路径采用 JSON response_format 与提示词，而不是在该路径直接调用四个独立函数工具。

### 4.3 _create/_update/_delete：真正发生变化的位置

三个函数分别从第646、708、751行开始。_create_memory 新建 UUID、文本 MD5 和创建时间，写向量库，再用 SQLiteManager.add_history 记录 ADD。MD5 是内容标识字段，不是语义相似度。_update_memory 保留 ID、created_at 与身份，重算文本 embedding/hash，新增 updated_at，记录旧文本与新文本。它构建新 metadata，不能假定所有自定义旧 metadata 都自动完整合并。_delete_memory 移除当前向量项，并在历史库写 DELETE/is_deleted=1。

先写向量，再写历史，不是跨库事务。异常或并发存在不一致风险；这里只解释静态路径与单写入演示，没有完成压力/并发或崩溃恢复验证。SQLiteManager.get_history 返回的字典不含 is_deleted，本次删除标记直接从真实 SQLite 表查询，避免把接口字典当表的全部字段。

### 4.4 search：读到事实尚未回答问题

Memory.search 第473行，query 字符串、limit 默认100，同样要求身份过滤。它调用 _search_vector_store 第533行，将 query 嵌入并查询后端，再用原 MemoryItem Pydantic 模型组织输出，包含 ID、memory、score、时间及身份等。**字典展开**用于组合字段；.model_dump() 把数据模型变成普通 dict。score 意义受后端距离约定影响，本 demo 是单位向量点积。

返回 results 不是最终自然语言回答。应用还需要把相关记忆和用户问题传给回答 LLM。此实验没有该回答模型，不能报告问答准确率。对于“以前住哪里”，仅从活动库搜索可能找不到被更新掉的北京，需要历史读取/原消息或时间化设计。


### 4.5 本轮实测的调用成本与失败边界【必须会】

[contracts_trace.json](复现/outputs/contracts_trace.json)记录14项边界/契约检查，原源码与旧结果未改。在临时SQLite库上观察到：

- 给add传非空filters/metadata字典，会在原字典上写入user_id；_create还给metadata加入data/hash/created_at。额外filter如tag只用于查询，未自动复制到存储payload，应另在metadata中指定。
- 更新时保留UUID/created_at，但旧custom字段若新metadata未给出就消失。created_at/updated_at是操作写入时间（US/Pacific格式），不是用户陈述事实发生或生效时间，不能直接回答“什么时候搬家”。
- 重复Hangzhou得到NONE、活动存储和历史不变，仍发生2次Provider调用；BAD_JSON提取失败后候选变空，仍进入更新阶段并共调用2次。它不是“没保存所以没花模型调用”。
- 缺身份键被拒绝；filters={'user_id':None}却能通过原代码的键存在检查，当前临时库检索返回空。源码要求至少存在一个身份键，不等于已校验其值为非空字符串。本demo不验证多租户安全隔离的所有误用。
- infer=False会跳过system，但保存assistant等非system消息，不调用Provider；它是原文原样记录路径，没有去重或事实抽取。
- 更新响应先给不存在数字ID99的UPDATE、再给有效ADD，原代码记录错误后仍执行ADD，结果只含成功ADD。这个构造直接说明按动作继续执行和部分成功，顶层返回不是事务完成证明。
- 通过临时替代历史对象故意让add_history抛RuntimeError，直接执行原_create_memory后，向量库已有1条、历史库0条。它证明两步之间没有跨库原子回滚；不代表真实运行发生了数据库故障，也没有测试完整崩溃恢复。

最后两种错误为有意注入；终端的BAD_JSON/ID99错误日志伴随检查退出码0，不是自然语言模型成功或工程无bug。输出含阶段调用、真实payload和部分结果，不能把绿色检查掩盖这些限制。

## 5. Mem0g：关系结构与时间信息

论文 §2.2 的未编号表示 $G=(V,E,L)$：V 是实体节点集合，E 为有方向关系边，L 为节点语义类型；三元组 $(v_s,r,v_d)$ 表示源实体、关系名、目标实体。节点带实体类型、浮点 embedding $e_v\in\mathbb R^d$ 和创建时间 $t_v$。这是图数据结构，不能写成一个固定 [B,L,d] 网络张量。

【建议会】例如 (Alice,lives_in,Beijing)，Alice:Person，Beijing:City。新数据先抽取实体与类型，再生成关系；对源/目标实体嵌入搜索相似旧节点，阈值 t 用于决定是否复用节点，然后插入关系、解决旧边冲突。t 表示相似阈值，t_v 是时间，不能混为一谈。复用同一实体避免“Alice”和“alice”产生不必要的图碎片；误合并同名不同人则会污染关系。

图3从左至右为消息→实体抽取/关系生成→冲突检测→更新解析→图存储。下方搜索已有节点供冲突模块判断。论文提出两种检索：以查询实体为锚点取入边/出边，及按语义相似检索文本化三元组。结构允许关系组合，但不会自动保证多跳推理正确。

重要版本差异：论文第6页说冲突旧关系标为 invalid，保留以支持时间推理；锁定源码 MemoryGraph._delete_entities 第289行起，用 Cypher 的 DELETE r 物理删除关系。本文没有把这份图代码解释成完整的时间有效区间系统。图搜索阈值 self.threshold=0.7，合并源/目标节点时调用阈值0.9，它们也不能无条件等同论文抽象 t。基础向量库的 DELETE 历史标记与图边的 invalid 概念不相同。

## 6. 实验：把结论限制在它真正测量的范围

### 6.1 数据、指标和公平性

LoCoMo 约10组长对话，每组约600个对话单位、26k token，多会话，平均约200问题。论文评测单跳、多跳、开放域、时间问题；排除了 adversarial/unanswerable 类。因此结果不证明拒答/缺失记忆识别能力，也不是任意人群的在线产品 A/B。

F1 衡量答案与参考的词重合，BLEU-1 是单词级精度指标，J 是独立 LLM judge 的语义评判。词面相似可以遮住“March→July”这样的事实错误；judge 补充语义判断，但仍有自身提示词/偏好误差。§3.2 因 J 随机性报告10次独立运行的均值±1标准差；不能自动理解成全部抽取、存储、回答模型完整重训重跑10次，也不是置信区间。

记忆抽取/更新使用 GPT-4o-mini。基线含已有 LoCoMo 结果、重跑 A-Mem、LangMem、Zep、RAG 和全上下文。RAG 块长128到8192，top-k仅1或2；本文改进不意味着击败所有现代混合检索、重排、查询改写 RAG。OpenAI 行来自当时 ChatGPT 界面方式导入对话并给回答器全部生成记忆，不能推广为当前 ChatGPT 产品的普遍排名；该方法访问全部记忆与查询选择召回的预算也不相同。

Token 用 cl100k_base 统计检索后给回答器的上下文。它不是所有历史写入、摘要、抽取、更新调用的累计计费量。Search latency 是检索；Total 是检索+回答生成，不含整个历史构建成本。不能从表2“总延迟”断言长期写入成本很低。

### 6.4 评分、延迟和标准差的计算例【建议会】

词重合F1可写 $F_1=2PR/(P+R)$：P是预测词匹配数/预测词数，R是匹配数/参考词数，返回[0,1]浮点，表中可乘100为百分比。示例参考[住,杭州]、预测[住,杭州,北京]，P=2/3、R=1，F1=.8；即便包含相互冲突城市，词面分仍可高。归一化、重复词计数、无匹配等细节依评估脚本，例子只是解释量纲，没有运行原指标。BLEU-1使用unigram匹配精度，常规BLEU还涉及brevity penalty；本地未重跑论文评分，不能把单项词重合当judge语义正确。

J是LLM judge结果的聚合百分比；“66.88±.15”中的.15为论文声明的重复run标准差，不等于±.15的95%置信区间。模型回答、judge模板、调用随机性各可能影响结果，不能只凭表中的小方差推出全pipeline对所有输入稳定。No adversarial类意味着这些结果也未衡量“证据缺失时是否拒答”。

p50/p95是延迟样本分布分位数，不是均值±标准差，也不是吞吐率。Mem0g比Mem0总体J高1.56个百分点，3616/1764≈2.05倍回答上下文token，p95 total 2.590/1.440≈1.80倍，体现质量/开销交换。cl100k_base仅用于此评估的token统计，demo的64维词哈希并不等于这个tokenizer；写入抽取/更新调用成本仍需另外记账。图4的log右轴用于跨度大时显示延迟，不能按曲线上像素距离计算线性秒数。

~~~python
response = remove_code_blocks(response)
new_retrieved_facts = json.loads(response)["facts"]
new_message_embeddings[new_mem] = messages_embeddings
~~~

一句话：从模型文本取候选，并缓存每条候选的向量。response最初str，remove_code_blocks仍str；json.loads转dict，取facts变list[str]；每次new_mem为单事实str、messages_embeddings为[d]浮点。缺键、坏JSON等进入except把事实列表设空，但并不立即return。json_object响应请求不能保证替代provider遵循schema；候选不是确认事实。

原写入关键段：

~~~python
metadata["data"] = data
metadata["hash"] = hashlib.md5(data.encode()).hexdigest()
self.vector_store.insert(vectors=[embeddings], ids=[memory_id], payloads=[metadata])
self.db.add_history(memory_id, None, data, "ADD", created_at=metadata["created_at"])
~~~

一句话：先活动库写入，再独立记录操作。data.encode默认UTF-8；MD5.hexdigest返回32位十六进制str，只是内容hash，不决定embedding相似度。insert的三个列表均长1，vectors是[1,d]的Python列表；metadata不是复制，而被原地加入字段。第三行成功后若第四行失败，没有跨库rollback，临时注入已证实。UUID、timestamp生成与向量内容是不同字段。

检索组织原段：

~~~python
embeddings = self.embedding_model.embed(query, "search")
memories = self.vector_store.search(query=query, vectors=embeddings, limit=limit, filters=filters)
~~~

一句话：按身份取候选后交给输出模型格式化，不生成最终回答。query为str→embedding[d]→memories为变长对象list→MemoryItem.model_dump()→list[dict]→api_version包装。**字典展开把模型输出/身份/metadata合并，后出现同名键会覆盖前项；不是矩阵广播。ThreadPoolExecutor的with会管理线程生命周期，Future.result传播未捕获错误；SQLite lock+connection上下文只包自己那张库的写入，不涵盖远端模型/另一库。
