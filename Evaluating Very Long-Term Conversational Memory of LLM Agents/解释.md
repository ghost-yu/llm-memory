# LoCoMo：论文与代码精读

这篇是评测论文。它不提出一种必须装进LLM的新记忆网络，而是提出长会话数据生成/人工修订流程，以及问答、事件概括、多模态对话三个任务。要理解“记住了”，需要分开看：检索是否找到了证据、回答是否正确、是否把人物和时间对应对。

## 2. 人机数据流水线与图3

【必须会】生成对话的记忆系统和被评测的记忆系统是不同对象。生成器需要人物设定与事件图保障连贯，不能把生成时的完整事件图直接当测试LLM的可见答案库。

从图3左到右：两个人物代理分别读取persona、事件、当前会话和历史记忆；生成一句响应或分享/回应图像；新对话转为observations，session结束时形成摘要；这些为后续生成提供记忆。右侧人工编辑纠正长期一致性、替换无关图片、核实事件。连线是信息/调用关系，LLM块负责文字推断，记忆库/检索/人工操作本身不由反向传播训练。

### 2.1 人物与时间事件图

§3.1从MSC中4–5句话的persona出发，用gpt-3.5-turbo扩展为身份、习惯、关系、经历等。§3.2用text-davinci-003生成最多25个事件，跨度6–12个月，每次迭代k=3项以维持时间/因果连贯。

论文未给这部分编号训练方程，主要用符号$G$、$e_i$、$t_i$、$l=(e_i,e_j)$：G为事件集合及因果关系；e_i是事件描述str，t_i为事件发生日期，l为从前事件到后事件的关联。例如“领养狗”先于“与邻居狗见面”，后续聊天应符合此前设定。箭头不自动证明真实因果，只是用来控制合成叙事的标注关系。

### 2.2 短期、长期、反思

每次会话k的文本$h_k$变为摘要$w_k$；每条对话$h_{kj}$变为观察$o_{kj}$。论文称摘要为短期记忆、观察为长期记忆，随后响应依赖最近摘要、相关观察、当前会话、persona，以及上次/本次会话之间发生的事件：

$$\{e_i\in G\mid t_k^s<t_i^e<t_{k+1}^s\}.$$

这是论文的未编号条件记法。$t_k^s$为会话日期，$t_i^e$为事件日期；先筛时间区间，再把相关事件文本放入提示。输出是一组事件对象，不是张量attention mask。区间端点事件具体归属仍要由实现定义，不能默认等号两边同时包含。

数据类型：persona:str；session:list[turn dict]；date_time:str；observation为人物对应的断言文本和来源ID；summary:str；LLM提示token为[L]整型，批处理可为[B,L]；retriever输出候选索引[K]和浮点分数[K]。论文没有规定新神经记忆的hidden_size/heads/loss。

正文的Hs/Hl下标在个别句子中有交叉，例如观察已写长期Hl、后文又写retrieved observations∈Hs。应按实体角色理解并查实现，不凭一个下标把摘要和观察的用途倒置。

### 2.3 图像与人工修订

分享图像时，LLM构思caption→转换关键词→网络检索图片；收到图像时用BLIP-2生成caption，再结合persona生成反应。用于QA和事件概括时图像替换成caption；只有多模态对话任务直接使用视觉内容。因此在QA上高分不证明视觉记忆可靠。

人工编辑约15%对话轮次，替换/删除约19%图像。这说明纯生成输出有明显质量问题，不能忽略人工阶段而把数据称完全自然真实对话，也不能把生成器自身有记忆当成被评测模型有同等能力。

### 2.4 图3方向、参数与事件日期例子

【必须会】[图3渲染](图片/page-5.png)中，Ongoing Session实线进入Retriever；Retriever下接Observations（长期记忆），再有Reflection框表示会话末更新；Short-term memory框也标会话末更新。Persona statement和Events自上方进入Prediction，短期/长期内容供其生成Response，输出再进入Human Editing。Image Reaction/Image sharing由虚线分支连接当前会话/Prediction，表示可选图像操作；不是梯度截断或另一条训练loss。人工框中的勾叉表示修订一致性，不能当自动准确率。

模型LLM/embedding/BLIP-2有外部已训练参数；检索索引/记忆字段/事件筛选/人工编辑不训练参数。图3用于数据生成的推理回路，与§3.3另一个MiniGPT-5训练任务分开。reflection概括自我及另一人物的经历，不是PyTorch backward。

完整一轮：session若干turn dict→检索旧observations:str列表/相关度→连同persona:str、近期摘要:str、事件:str列表进入prompt→token序列[L]→Prediction响应str/可选图像说明→人工修订→下一会话记忆。图本身未规定B/head/d维度，不应套用新记忆网络。源码位置：generative_agents/memory_utils.py的get_session_facts/get_session_reflection/get_relevant_context；event_utils.py的get_events；conversation_utils.py的图像/caption函数。这里只静态对应，未运行生成器、图片搜索或API。

未编号事件条件的微型例子：会话日期t_k^s=1月10日、t_(k+1)^s=2月1日，1月20日事件满足两个严格不等式进入提示；恰1月10日/2月1日不满足。i是事件编号，k是会话编号，日期是可比较时间值，不是向量；实际字符串解析和端点处理仍需按生成代码核查。这个例子阐明论文条件，不宣称已重跑全部事件生成。

## 3. 三个任务、标签与输入输出

### 3.1 问答【必须会】

问题给一个长对话历史，要求回忆或组合信息。当前数据category与代码映射：

| category | 类型 | 所需能力 |
|---|---|---|
| 1 | Multi-hop | 跨多个会话组合证据 |
| 2 | Temporal | 解析会话日期/相对时间/事件顺序 |
| 3 | Open-domain | 对话信息结合常识/世界知识 |
| 4 | Single-hop | 取一个局部事实 |
| 5 | Adversarial | 识别无法从历史回答的问题 |

qa字段question、answer、category、evidence；evidence包含D会话:轮次ID。例如D2:6指第2会话第6条，用来评估召回。speaker必须保留，单纯找出关键词不能证明事实属于问句中的人物。本文不把多跳和时间混为同一类。

### 3.2 事件概括【建议会】

给某个时间范围的对话，输出某个人物事件和时间/因果关系，再与人工核实事件比较。event_summary是该任务标注，不是可任意给QA回答器的生成摘要；session_summary为生成式会话摘要，observation为生成式断言，三者不能混称“gold memory”。

FactScore的适配方式：把参考/生成概括拆成原子事实，算支持生成事实的precision与覆盖参考事实的recall，再求F1。拆分和事实匹配本身需要额外模型/协议；不是只运行词面F1就完成事件事实评分。

### 3.3 多模态对话生成【建议会】

给历史和当前状态，生成文字/图像回应，测词面、语义及MMRelevance，检查是否延续人物叙事。训练使用另外生成的50组未人工过滤对话，MiniGPT-5从MMDialog微调checkpoint出发。生成合适图像、生成文字caption、记住既往事件分别是不同能力。

## 4. 评分公式：实际代码比“F1”两个字更具体

以下公式帮助解释实现，非论文编号新模型损失。原函数位于 [evaluation.py](代码/locomo-official/task_eval/evaluation.py)。本demo通过AST执行normalize_answer、f1_score、f1、exact_match_score、eval_question_answering五个原函数，不加载未安装BERTScore模型。

### 4.1 单答案词面F1【必须会】

normalize_answer删标点/逗号、转小写、移除a/an/the/and、整理空白；随后PorterStemmer词干化。预测/参考分别有词频多重集P、A，重合词数c用Counter交集求和：

$$p=\frac{c}{|P|},\qquad r=\frac{c}{|A|},\qquad F_1=\frac{2pr}{p+r}.$$

预测“red car”，参考“red fast car”，c=2、p=1、r=2/3，F1=0.8；demo真实得到0.8。没有共同词时函数直接0，包括空答案，不会除0。Counter(&)取每个词的最小频次，不能只数unique词。

owner为普通函数，无self；输入两个字符串，输出数值标量，不改模型状态。f1_score在category2/3/4调用；category3参考还先按分号取第一段。EM函数按词集合比较，忽略顺序/重复，不能无条件称严格原字符串一致。

### 4.2 多答案F1【必须会】

category1调用f1：预测/参考都按逗号分成子答案，对每个参考项求最好匹配预测项，再对参考项取均值：

$$\mathrm{score}=\frac1{|A|}\sum_{a\in A}\max_{p\in P}F_1(p,a).$$

它没有额外预测数量的全局惩罚。预测“apple, banana, invented”，参考“apple, banana”，仍得到1。demo用原函数确认这个性质。不要把它理解成把所有预测词合起来求普通precision，也不要将无关额外答案获得满分解释成全部回答正确。

### 4.3 对抗题与缺失context的特殊分支

category5的原eval_question_answering判断输出是否含“no information available”或“not mentioned”，有就计1；不是语义级拒答judge。输出“Not mentioned, but I invent that she lives in Paris.”仍计1，本次已观测。官方gpt_utils在category5还构造二选一：参考候选与Not mentioned，并把模型选择映射回文本。因此这个设置不能直接代表真实自由问答中的拒答能力。

eval_question_answering参数qas为list[dict]、eval_key默认prediction、metric默认f1；返回(每题分数list, lens=0.0, 每题recall list)，打印统计，metric参数并没有在主要分支选择任意新指标。名字all_ems里的值实际主要是F1/对抗条件分，不是统一EM。

如果eval_key+'_context'缺失或evidence为空，代码给recall=1；没有证据不是检索成功。demo的缺context探针用错答案仍得到recall1，解读和本实验不会把这些行纳入检索覆盖率。

### 4.4 证据覆盖率【必须会】

对第q题标注证据集合$E_q$和取回ID集合$R_q^k$：

$$\mathrm{recall}_q@k=\frac{\sum_{e\in E_q}\mathbf1[e\in R_q^k]}{|E_q|},\qquad\overline R@k=\frac1Q\sum_{q=1}^Q\mathrm{recall}_q@k.$$

这里Q为实际纳入题数；每题先算比例再平均，不是把全部证据混在一个总分母。多跳题标注3条证据取回2条，得2/3；这不代表推理正确。Summary检索ID为S会话号时，原代码按相关会话命中估计recall，因此它与精确turn命中不是同一粒度预算。

当前数据的9处evidence字符串无法精确匹配turn IDs，例如一个字符串含多个ID、D:11:26、D30:05。demo原样保留并算未命中，列出所有异常，不默改注释来抬分。若后续清洗，要发布变更规则和前后两组结果。

## 5. 真实代码路径与配置

入口task_eval/evaluate_qa.py解析--data-file/--out-file/--model/--use-rag/--rag-mode/--retriever/--top-k；读取当前sample，给具体后端get_*_answers，再调用原指标和统计。原生成脚本需服务/API/模型，不能因文件存在就宣称完整复现。

gpt_utils构造时间、speaker、原text/caption，提供短句答题指令；根据context预算拼接；锁定版本的会话顺序与截断可能先保留旧内容，详见§7.4原函数实测。RAG模式从dialog/observation/summary中取候选。检索源必须是可见对话或生成记忆，evidence/answer/event gold不是可参与生成答案的索引训练字段。可用gold做诊断oracle，但必须明确标记，不当真实系统成绩。

rag_utils的mean_pooling输入token_embeddings[B,L,d]和mask[B,L]：mask[...,None]变[B,L,1]；无效位置置0，沿L求和[B,d]，除每条有效token数[B,1]，获得句向量。此处是推理池化，无本论文训练loss。

我们没有运行官方DRAGON/DPR/Contriever/OpenAI后端。静态发现当前rag_utils部分路径值得复跑前检查：init_query_model的contriever分支引用未定义context_tokenizer；get_embeddings的contriever将inputs当含attention_mask的字典，但前面使用它为输入文本集合；某些辅助上下文函数固定range(1,20)，未必覆盖公开子集中32会话。不能把这些路径逐一说成实际跑通，主路径的具体覆盖还需按调用关系核对。

## 7. 小demo：1536道真实题的证据检索

[运行说明](复现/README.md)、[脚本](复现/scripts/demo_locomo.py)、[实际结果](复现/outputs/results.json)。状态 **部分成功**。

真实公开locomo10数据、原五个评分函数；检索使用本地BM25，不是原DRAGON。每条document由会话日期、speaker、text和已提供caption构成；只用question查询，排名完成后才读取answer/evidence评分。没有答案生成器，没有给模型gold，未调用网络/付费/下载模型。

BM25教学公式（非本论文新公式）：

$$\mathrm{BM25}(q,d)=\sum_{w\in \operatorname{unique}(q)}\log\left(1+\frac{N-df_w+0.5}{df_w+0.5}\right)\frac{tf_{w,d}(k_1+1)}{tf_{w,d}+k_1(1-b+b|d|/\max(1,\overline{|d|}))}.$$

N为同对话文档数；df为包含词的文档数；tf为词频；长度是过滤常见词/Porter词干后的计数。demo k1=1.5、b=.75，倒排表召回匹配词；无得分/同分按原时间插入顺序。它是词面检索，不能自动解析相对日期、同义词或多跳；每个对话单独索引，不跨用户样本混合。

### 7.2 原评分代码、变量与协议陷阱

【必须会】单答案原代码在evaluation.py，作用是计词频重合，出现在回答生成后：

~~~python
prediction_tokens = [ps.stem(w) for w in normalize_answer(prediction).split()]
ground_truth_tokens = [ps.stem(w) for w in normalize_answer(ground_truth).split()]
common = Counter(prediction_tokens) & Counter(ground_truth_tokens)
num_same = sum(common.values())
if num_same == 0:
    return 0
precision = 1.0 * num_same / len(prediction_tokens)
recall = 1.0 * num_same / len(ground_truth_tokens)
f1 = (2 * precision * recall) / (precision + recall)
~~~

API：PorterStemmer.stem词干化；Counter计重复次数，&取每词最小次数；列表推导式逐词转换，sum合计。预测/参考str→归一化str→token:list[str]长P/A→词频字典→共同词数int→P/R/F1 float标量。变量precision对应预测分母，recall对应参考分母，不是检索evidence recall。num_same=0先返回，免空串除零，但空F1=0和空EM=True不同。

例预测apple apple、参考apple：c=1、P=.5、R=1、F1=2/3；实测确认多重集惩罚重复预测。cars/car经词干都car，F1=1，集合EM则没有该词干步骤。不应与A-MEM的set token F1直接混用。

原召回片段：

~~~python
if eval_key + '_context' in line and len(line['evidence']) > 0:
    if line[eval_key + '_context'][0].startswith('S'):
        sessions = [e[1:] for e in line[eval_key + '_context']]
        recall_acc = float(sum([ev.split(':')[0][1:] in sessions for ev in line["evidence"]]))/len(line['evidence'])
    else:
        recall_acc = float(sum([ev in line[eval_key + '_context'] for ev in line["evidence"]]))/len(line['evidence'])
    all_recall.append(recall_acc)
else:
    all_recall.append(1)
~~~

目的：把取回ID与gold evidence对照，处于检索和回答结束后的诊断，不把gold当索引输入。startswith只检查**第一**context ID；第一条S2、第二条D1:1时全按session模式，D1:1可能不按精确ID匹配。e[1:]和ev.split(':')[0][1:]剥首字母得到会话号str，带零补位的号也可能不匹配，不能把它称通用ID解析器。

| 变量 | 来源/意义 | 类型 / shape |
|---|---|---|
| line | 当前qas[i] | dict，Q个中一个 |
| eval_key+'_context' | 返回的检索ID字段 | list[str]长K，本demoturn IDs |
| line['evidence'] | gold标注 | list[str]长E，可重复或异常 |
| sessions | context转换的会话号 | list[str]长K |
| recall_acc | 命中比例 | float标量 |
| all_recall | 各题比例累计 | list[float]长Q |

§4.4把E写成集合方便解释，**原实现和demo保留标注列表次数，不自动去重**：evidence=[D1:1,D1:1,D2:1]、取回D1:1得2/3，而非set语义1/2。上下文不存在或evidence=[]返回1是默认，不是成功检索；evidence非空但context=[]会在[0]处IndexError。本demo排除空evidence，正常k>0返回非空context，所以1536题平均没有利用这两个默认抬分分支。

category3只用参考分号前第一段；metric='exact_match'实际仍普通F1；未知category6 ValueError；预测list被某个前置判断识别，但后续f1_score仍要求str，实测AttributeError，不应宣称支持list预测。category5仅匹配拒答关键词，包含“NOT not mentioned”也得1。函数不改qas，只打印；空batch返回([],0.0,[])。这些是原指标性质，不是模型能力评价。

### 7.3 原张量池化：数值、广播与零分母

【建议会】原rag_utils.py函数把token embedding汇成句向量：

~~~python
def mean_pooling(token_embeddings, mask):
    token_embeddings = token_embeddings.masked_fill(~mask[..., None].bool(), 0.)
    sentence_embeddings = token_embeddings.sum(dim=1) / mask.sum(dim=1)[..., None]
    return sentence_embeddings
~~~

它在编码器forward之后，不是编码器本身。Tensor.masked_fill返回新Tensor；mask[...,None]插末维[B,L,1]，bool将非零转True，~取反，所以无效位置为True而填0，广播到每个d特征；sum(dim=1)消L，得到[B,d]；分母mask.sum(dim=1)[...,None]为[B,1]，除法广播到d。没有在函数中加no_grad，也没有clamp分母。

二值mask前提下的教学式（非论文编号公式）：

$$
z_{b,h}=\frac{\sum_{\ell=1}^{L}m_{b,\ell}x_{b,\ell,h}}
{\sum_{\ell=1}^{L}m_{b,\ell}},\qquad m_{b,\ell}\in\{0,1\}.
$$

b批次索引1..B，ell token索引1..L，h特征索引1..d，x浮点[B,L,d]，m二值[B,L]，z浮点[B,d]。先屏蔽token、逐特征求和、按有效token数除；有效长度应>0。不要与BM25长度归一化混为同一个公式。

真实CPU torch小例：token=[[2,4],[4,6],[100,100]]、mask=[1,1,0]，和[6,10]除2→[3,5]。全零mask为0/0，实测NaN；非二值[2,1,0]，分子仍是[6,10]（bool只认非零），分母3，输出[2,10/3]，不是标准加权平均。输入未原地修改，requires_grad输入的有效两token各梯度[.5,.5]、被屏蔽token为0，说明该函数本身可被autograd追踪；测试梯度不等于本论文训练了检索器。

[trace_pooling.py](复现/scripts/trace_pooling.py) AST运行原体，PyTorch2.14.1+cpu/Python3.12.14来自已存在Titans venv，不加载真实tokenizer/encoder/checkpoint，不import整个rag_utils；5项检查通过。张量变量的名字/shape对应原参数，输出在 [pooling_trace.json](复现/outputs/pooling_trace.json)。不把函数成功当DRAGON/Contriever路径成功。
